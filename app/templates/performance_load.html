How to read this test Protocol & interpretation

Arrivals follow a seeded {{ view.protocol.arrival|lower }} schedule; runs with the same settings receive identical traffic. Inputs and outputs are drawn from each class's length histograms; output length is enforced by the token limit. A request meets its SLO when it completes and its user-visible first token, token time and answer time are within the class targets. Dispatch lag is added to user-visible timings.

A step passes when at least the target share of all arrivals, and of each class, met the SLO, and the client kept up (no dropped arrivals, dispatch lag p99 ≤ 100 ms). The sustainable rate is the highest passing rate. It is established only when a higher rate failed because of the server; otherwise it is a lower bound.

The result applies to this workload, SLO and deployment state. Other traffic on the deployment during the test affects it; see vLLM monitoring. Expected arrivals: {{ view.protocol.expected }} · request timeout {{ view.protocol.timeout }}.
